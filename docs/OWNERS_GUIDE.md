# 해결 담당(own)·팀별 할 일(act) 작성 규칙

각 원인 항목에 두 필드를 넣는다. 예전 `fix` 필드는 쓰지 않는다(`own`과 함께 있으면 `node tools/validate.cjs`가 오류로 본다).

```js
own: ['srv', 'dba'],          // 첫 항목 = 주 담당(근본 원인을 없애는 곳), 나머지 = 실제로 할 일이 있는 곳
act: { game: '...', infra: '...', ext: '...' },   // own에 있는 팀마다 하나씩, 없는 팀은 넣지 않음
```

## 담당 코드 (src/js/data.js owners)
| 코드 | 팀 | 이름 | 범위 |
|---|---|---|---|
| cli | game | 클라이언트 개발 | 게임 클라이언트 코드: 프레임·GC·로딩, 보간·외삽·예측, 클라이언트의 네트워크 처리(하트비트 보내기·자동 재접속 포함) |
| srv | game | 서버 개발 | 게임 서버 코드: 틱·스레드·락, 동기화 설계, 접속 처리(accept 루프·listen 인자), 하트비트 응답·끊긴 연결 정리, 소켓 옵션, 쿼리·트랜잭션 설계 |
| net | infra | 네트워크 인프라 | 회선과 IDC 네트워크 장비(스위치·라우터·방화벽·로드밸런서·DDoS 방어), 클라우드 네트워크 ACL·VPC 라우팅·로드밸런서, 통신사·피어링 |
| sys | infra | 서버 인프라 | 서버 장비·클라우드 인스턴스(보안 그룹·연결 추적 포함), OS·커널 설정, NIC, 배포·모니터링 환경 |
| dba | infra | DB 인프라 | DB 서버·스토리지, DB 설정·복제·백업, 캐시 서버 |
| ext | ext | 외부 | 유저 PC·집 네트워크, 통신사 구간(우리 계약 밖), 클라우드 사업자. 직접 고칠 수 없어 안내·요청·우회로 대응 |

범위 칸은 `data.js`의 `owners[].desc`와 담당 구분 장의 표와 같은 문장이다. 고칠 때는 세 곳을 함께 고친다.

act 키: game = cli·srv, infra = net·sys·dba, ext = ext.

## 주 담당 정하는 법
- 근본 원인이 있는 곳, 또는 그 원인을 없앨 수 있는 곳이 주 담당이다.
- 클라이언트 코드 → cli, 서버 코드·동기화 설계 → srv.
- 쿼리·인덱스·트랜잭션 설계 → srv. DB 장비·설정·복제·백업 → dba. 둘 다 할 일이 있으면 둘 다 넣고 원인에 가까운 쪽을 앞에.
- 코드에서 거는 소켓 옵션(TCP_NODELAY·버퍼 크기 등), 스키마 설계 → srv. 커널 sysctl·NIC·인스턴스, 크론·서버 백업 작업 → sys. DB 체크포인트·캐시 서버(Redis 등) 운영 → dba.
- 우리 IDC·클라우드 네트워크 장비, 우리가 계약한 회선·피어링 → net.
- 유저 집 와이파이·공유기·PC·모바일 기기 → ext 주 담당. 게임이 완화할 수 있으면(보간 버퍼, 네트워크 상태 표시, 재접속) cli·srv를 함께 넣는다.
- 통신사망 안쪽 문제: 우리 인프라팀이 경로 변경·피어링·에스컬레이션으로 실제로 고칠 수 있으면 net 주 담당 + ext, 통신사만 고칠 수 있으면 ext 주 담당 + net(에스컬레이션).
- 클라우드 사업자 한도·장애 → 인스턴스·구성을 바꿔 피할 수 있으면 sys(또는 net) 주 담당 + ext.
- 함께 넣는 담당은 할 일이 실제로 있을 때만. 억지로 늘리지 않는다. 보통 1~3개.

## act 쓰는 법
- 각 조치를 실제로 하는 팀의 칸에 넣는다. 기존 문장을 고칠 때는 조치를 빠뜨리지 않는다.
- 빠진 쪽이 분명하면 짧게 보탠다. 예: 회선 문제에 게임팀의 완화책, 코드 문제에 인프라팀의 확인 지표.
- 할 일을 짧은 구절로 나열한다(쉼표로 구분, 마침표로 끝). 비전문가가 읽을 수 있게 쓰고 용어는 docs/TERMS.md의 표준 용어를 쓴다.
- ext는 “유저에게 무엇을 안내”, “통신사·클라우드 사업자에 무엇을 요청” 형태로 쓴다.
- 숫자, 설정·카운터 이름, 조건은 바꾸지 않는다.

## 검수 뒤 추가한 규칙
- **하트비트는 클라이언트가 보내고 서버가 응답한다.** 집 공유기·통신사 CGNAT의 매핑은 안쪽에서 나가는 패킷으로만 확실히 갱신된다(RFC 4787). 로드밸런서·보안 그룹·방화벽은 어느 방향 패킷으로도 갱신된다. 그래서 표준 문구는 “클라이언트: 가장 짧은 유휴 타임아웃의 절반 이하 간격으로 하트비트 보내기, 끊기면 자동 재접속. 서버: 하트비트에 응답하고 일정 시간 못 받으면 연결을 먼저 정리, 세션 토큰으로 이어 받기.”
- **클라우드 보안 그룹·ENI 연결 추적 → sys**(인스턴스 단위 설정). 클라우드 네트워크 ACL·VPC 라우팅·클라우드 로드밸런서 → net.
- **한 칸에 같은 팀 담당이 둘이면 own 순서(주 담당 먼저)로 접두어를 쓴다.**
- **listen backlog 넘침 → srv 주 담당**(listen 인자·accept 루프가 실제 한계), sys는 somaxconn·SYN 쿠키.
